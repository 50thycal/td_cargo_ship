# Straitwatch (td_cargo_ship)

## Working with the player on design rounds

For a larger design or planning round, the default hand-off is a **review page**:
- a brainstorm with many ideas;
- a plan with open questions;
- specs or numbers to confirm before a build.

The page is a published HTML artifact where the player marks each item, writes notes and answers the questions. The next session reads the saved marks back. Follow the `review-page` skill (`.claude/skills/review-page/SKILL.md`).

Skip it for small asks (one or two questions, a single bug, a quick tweak): ask those in chat.

## The map rebuild hub (the player's main channel)

The player follows the map rebuild on one page and doesn't read chat: https://claude.ai/artifact/LeZK1fL9QFusN5qQNAoAmb, generated by `tools/v3/map-rules/page.mjs` from `tools/v3/map-rules/plan.mjs` (status, needs, decisions), `rules.mjs` and `evidence.json`.

- Whenever the plan changes or a step finishes, update `STATUS` in `plan.mjs`, regenerate the page and republish it to the same URL (capabilities `db` and `tts`). Keep the doc in step: `node tools/v3/map-rules/page.mjs --doc`.
- Put a decision the player must make in `NEEDS`, with a new id (`r2-…`, `r3-…`). Never ask again what is already answered: read the page's `reviews` and `answers` collections first, move answered items out of `NEEDS`, and save the marks into `tools/v3/map-rules/review-<date>.json`.
- Keep chat replies short and point to the page.
- Every map change adds an entry at the top of that map's history in `src/v3/data/mapHistory.ts` (date, log version, what, why, and an updated `look`): the Test Lab's map notes show it.
